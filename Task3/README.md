# Задание 3. Векторный индекс базы знаний

## Вывод

База знаний Задания 2 (41 анонимизированный документ на русском) преобразована в
векторный индекс **FAISS** на эмбеддингах **`BAAI/bge-m3`**. Индекс готов к
семантическому поиску релевантных фрагментов по пользовательским запросам с
цитированием источника.

| Параметр | Значение |
|---|---|
| Эмбеддинг-модель | **BAAI/bge-m3** (Sentence-Transformers, локально) |
| Репозиторий модели | https://huggingface.co/BAAI/bge-m3 |
| Размер эмбеддингов | **1024** (float32) |
| База знаний | `Task2/knowledge_base/` — 41 документ (вымышленный мир на основе The Witcher) |
| Чанков в индексе | **1105** |
| Чанкинг | `RecursiveCharacterTextSplitter`, 1000 символов, overlap 150 |
| Векторная БД | FAISS (`index.faiss` 4.5 МБ + `index.pkl` 1.5 МБ) |
| Время: загрузка модели | ~98 c (CPU, первый запуск — с прогревом кэша) |
| Время: эмбеддинги + индекс | **~115 c** (1105 чанков, CPU) |

Модель выбрана в Задании 1: локальная многоязычная (база на русском, поэтому
англоязычные модели вроде `all-MiniLM-L6-v2` не подходят), конфиденциальность —
данные не покидают периметр. `bge-m3` не требует префиксов `query:`/`passage:`.

## Что в индексе

Каждый чанк хранит метаданные для цитирования и объяснений:
- `source` — имя файла-источника (например, `гаврила-из-зажопинск.md`);
- `title` — заголовок документа (первая строка `# …`);
- `chunk_id` — порядковый номер чанка внутри документа;
- `start_index` — позиция (символ) чанка в исходном тексте.

## Запуск

```bash
# Python 3.10–3.12 (под 3.14 нет колёс torch/faiss). Использован 3.10.
python3.10 -m venv Task3/.venv && source Task3/.venv/bin/activate
pip install -r Task3/requirements.txt

python Task3/build_index.py     # Task2/knowledge_base → Task3/index/ (+ build_stats.json)
python Task3/query_example.py   # примеры поиска
```

Скрипты самолокализуются: данные читаются из `Task2/knowledge_base/`, индекс
пишется в `Task3/index/`. Точные числа сборки — в `Task3/build_stats.json`.

## Пример запроса к индексу

`score` — расстояние L2 между нормированными векторами: **меньше = ближе**.

```
ЗАПРОС: Расскажи про Шальную Облаву и её призрачных всадников.
  [1] score=0.633 | «Шальная Облава» (шальная-облава.md, чанк #0, поз. 0)
      # Шальная Облава «…по чёрному небу пронёсся Шальной Загул — табун
      огненнооких … призраков на конских скелетах» …
  [2] score=0.645 | «Шальная Облава» (шальная-облава.md, чанк #1, поз. 827)
      Шальная Облава выглядит как кошмарная процессия скачущих высоко в небе
      призраков и мертвецов на лошадиных скелетах …

ЗАПРОС: Какие знаки использует ворожей в бою?
  [1] score=0.675 | «Ворожей» (ворожей.md, чанк #37, поз. 23365)
      Ворожей владеют так называемыми Знаками — разновидностью боевой простейшей
      магии … которые появляются у охотников на чудовищ после Испытаний …
  [2] score=0.710 | «Ворожейский Знаки» (ворожейский-знаки.md, чанк #0, поз. 0)
      Считается, что ворожейский Знаки просты, так как производятся без
      произнесения магической формулы …

ЗАПРОС: Кто такой Гаврила из Зажопинска и чем он занимается?
  [1] score=0.683 | «Гаврила из Зажопинск» (гаврила-из-зажопинск.md, чанк #0)
      … Гаврила из Зажопинск, прозванный Сивым Мерином … главный герой саги …
```

Запросы сформулированы в вымышленных терминах базы (Шальная Облава, ворожей,
Гаврила), поэтому релевантность подтверждает, что поиск опирается на индекс, а не
на память модели. Полный вывод по 4 запросам даёт `Task3/query_example.py`.

## Замечания

- Поиск использует **только эмбеддинги** (`bge-m3`), без LLM — генерация ответов
  будет в следующем задании (RAG-оркестратор).
- Индекс (`Task3/index/`) закоммичен как артефакт; модель (~2.3 ГБ) кэшируется в
  `~/.cache/huggingface` и в репозиторий не попадает.
- При нехватке памяти можно уменьшить чанки или взять модель полегче
  (`multilingual-e5-base`, 768-dim) — достаточно сменить `MODEL_NAME` в
  `build_index.py` и `query_example.py`.
