# Задание 4. RAG-бот с Few-shot и Chain-of-Thought

## Вывод

Реализован работающий RAG-бот: он ищет релевантные фрагменты в векторной базе
(FAISS из Задания 3), формирует ответ строго по найденному контексту и применяет
техники промптинга **Few-shot** и **Chain-of-Thought**. Если ответа в базе нет —
честно отвечает «Я не знаю.». Интерфейс — консольный REPL.

| Параметр | Значение |
|---|---|
| LLM | **Claude Haiku 4.5** (`claude-haiku-4-5`) — самая дешёвая модель; через Anthropic SDK |
| Эмбеддинги запроса | **BAAI/bge-m3** — тот же энкодер, что при построении индекса |
| Индекс | FAISS из `Task3/index/` (1105 чанков) |
| Извлечение | top-k = 4 ближайших чанка |
| Техники промптинга | Few-shot (2 примера) + Chain-of-Thought (System-промпт) |

Модель меняется переменной окружения `CLAUDE_MODEL` (выбор Задания 1 — Claude;
архитектура цепочки от модели не зависит).

## Цепочка RAG (что под капотом)

`scripts: rag_bot.py`

1. **Запрос** пользователя (REPL).
2. **Эмбеддинг** запроса энкодером `bge-m3` (тот же, что в индексе).
3. **Поиск** в FAISS: `similarity_search_with_score(query, k=4)` → ближайшие чанки
   с метаданными (`source`, `chunk_id`, `start_index`).
4. **Сборка промпта**: System (CoT) + Few-shot примеры + блок КОНТЕКСТ из найденных
   чанков + ВОПРОС (последним ходом).
5. **Вызов LLM** `client.messages.create(...)` (Anthropic SDK).
6. **Ответ** + источники возвращаются пользователю.

Это ручная цепочка (а не `RetrievalQA` «как чёрный ящик»), чтобы каждый шаг был явным.

## Техники промптинга

**Chain-of-Thought** — System-промпт требует сначала пошагового рассуждения, затем
итогового ответа. Формат фиксирован:
```
Рассуждение:
1. <шаг>
2. <шаг>
Ответ: <итог или «Я не знаю.»>
Источник: <файлы>
```

**Few-shot** — в диалог добавлены 2 примера «вопрос → ответ» из той же предметной
области (взяты из базы): один с найденным ответом, второй — с честным «Я не знаю».
Примеры идут отдельными ходами `user`/`assistant` перед реальным запросом (не как
prefill последнего хода — это запрещено в Claude 4.x).

**Честность / «Я не знаю»** — System-промпт запрещает внешние знания и домыслы.
Поэтому запросы о терминах, которых нет в анонимизированной базе («Геральт»
переименован в «Гаврилу»), и вопросы вне базы («столица Франции») приводят к отказу,
а не к ответу по памяти модели. Это и есть проверка работы RAG.

## Запуск

```bash
# окружение (переиспользует стек Задания 3 + Anthropic SDK)
source Task3/.venv/bin/activate        # или: python3.10 -m venv .venv && pip install -r Task4/requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...

python Task4/rag_bot.py                 # интерактивный REPL
python Task4/run_examples.py            # неинтерактивный прогон 7 демо-запросов
```

На тарифе Free Tier (5 запросов/мин) задайте паузу: `PACE_SECONDS=18 python Task4/run_examples.py`.

## Примеры диалогов

Полные диалоги — в [dialogs.md](dialogs.md): **5 успешных** ответов с рассуждением и
источниками + **2 случая «Я не знаю»** (переименованный «Геральт» и вопрос вне базы).

Кратко:
- «Кто такой Гаврила из Зажопинска?» → ворожей из Школы Дворняги, охотник на чудовищ (score 0.683).
- «Какими Знаками владеет ворожей?» → Толкач, Пузырь; появляются после Испытаний.
- «Кто такой Геральт из Ривии?» → **Я не знаю** (термин переименован, в базе его нет).
- «Какая столица Франции?» → **Я не знаю** (вопрос вне базы).

## Замечания

- Бот использует эмбеддинги (`bge-m3`) для поиска и LLM (Claude) только для генерации —
  это не одно и то же.
- Интерфейс (REPL) вторичен; ядро — корректная цепочка RAG. Модуль `rag_bot.ask()`
  переиспользуем для REST/Telegram-обёртки.
- Стоимость на Haiku 4.5 ≈ $0.0045 за запрос (вход ~3k + выход ~300 токенов);
  демо из 7 диалогов ≈ 3 цента.
